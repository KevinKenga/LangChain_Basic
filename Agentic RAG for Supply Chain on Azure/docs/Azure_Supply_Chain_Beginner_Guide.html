For macOS, using Terminal and bash. Every command is written out in full, with what it does, what you should see, and what to do if it fails.

What actually happened to us (real mistakes and fixes)

This guide was written first and then run for real. Fifteen things went wrong on the way. None of them was the user's fault, and all of them are already fixed in the steps below. They are listed here so that you recognise them if they happen to you.

0. Welcome - what you will build

You are going to put a small "question and answer" system into the cloud. You give it PDF reports about a supply chain. It reads them, stores them in a searchable form, and then answers questions about them in plain English.

You do not need to know anything about Azure to start. Every term is explained the first time it appears, and there is a small dictionary just below.

What you end up with:

  • A folder in Azure (called a resource group) that holds everything.
  • A place to drop PDF files.
  • A search index built from those PDFs.
  • A small program (a Function) that wakes up by itself when a new PDF arrives, reads it, and writes an answer.
  • Three ways to ask a question by hand.
  • One command that deletes everything and stops the bill.

1. Before you start

You need four things: an Azure account, the Azure command line tool, a Python environment, and the zip tool. This section checks all four.

☐ Step 1 - Have an Azure account

Open https://portal.azure.com in your browser and sign in. That page is called the portal - it is the clickable version of Azure. If you have no account, create a free one from that page first. You do not need to click anything else yet.

☐ Step 2 - Install the Azure command line tool

What this does: installs az, the program that lets you create Azure services by typing instead of clicking. We do not use Homebrew for this: on an Intel Mac Homebrew now refuses to install it (the error mentions directories are not writable: /usr/local/libexec). Instead we give the CLI its own private Python environment, which cannot disturb anything else.

First, find out which shell your Terminal uses. Look at the prompt, the text just before where you type. If it ends with bash or bash-3.2$, you have bash. If it ends with zsh or %, you have zsh. On this Mac it is bash, so the file we edit below is ~/.bash_profile. If yours says zsh, use ~/.zshrc in the same commands.

What this does: creates a private Python environment for the CLI in your home folder.

COPY
python3.11 -m venv "$HOME/azure-cli-venv"

You should see: nothing at all. A folder called azure-cli-venv appears in your home folder.

If it fails: python3.11: command not found means Python 3.11 is not on your PATH. Use the full path instead: /Users/msp/anaconda3/bin/python3.11 -m venv "$HOME/azure-cli-venv". Any working Python 3.11 is fine here.

What this does: installs the Azure CLI into that environment. This takes several minutes; let it finish.

COPY
"$HOME/azure-cli-venv/bin/pip" install azure-cli

You should see: a lot of download lines, ending with Successfully installed ... azure-cli-2.x.x ....

If it fails: a network timeout is worth one retry. Any other error: copy the last ten lines and ask for help.

What this does: adds the CLI folder to your PATH, so the word az works in every new Terminal window. Note the order: the folder goes at the end ($PATH:), never at the front. At the front, the CLI's own python and pip would take over, and then pip install -r requirements.txt tries to compile pymupdf and fails.

COPY
echo 'export PATH="$PATH:$HOME/azure-cli-venv/bin"' >> ~/.bash_profile
export PATH="$PATH:$HOME/azure-cli-venv/bin"

You should see: nothing. The first line writes the setting into ~/.bash_profile so it is applied in every new window; the second line applies it to the window you are in right now.

If it fails: if you use zsh, replace ~/.bash_profile with ~/.zshrc. If you are not sure, run echo $SHELL: it prints /bin/bash or /bin/zsh.

☐ Step 3 - Check that the tool answers

What this does: asks az to print its own version, which proves the install worked.

COPY
az version

You should see: a small block of JSON with "azure-cli" and "azure-cli-core" version numbers.

If it fails: az: command not found means this window has not loaded the PATH line yet. Run export PATH="$PATH:$HOME/azure-cli-venv/bin" again and retry. If it still fails, open a new Terminal window and run it there; the line in ~/.bash_profile is only read when a window starts.

☐ Step 4 - Check the Python environment

The project uses a venv (a private Python environment) that lives one folder above the project, at LangChain_Basic/.venv. That is why the path below starts with ../, which means "go up one folder".

What this does: asks whether that environment's Python exists.

COPY
ls ../.venv/bin/python

You should see: the path printed back, for example ../.venv/bin/python.

If it fails: a "No such file" message means the environment does not exist yet. Create it once with the next command. This command must be run from inside the project folder, which Section 2 sets up - so if you are not there yet, do Section 2 first and come back.

COPY
python3.11 -m venv ../.venv

You should see: nothing at all. A .venv folder appears next to the project folder.

If it fails: python3.11: command not found means Python 3.11 is missing. Install it from https://www.python.org/downloads/, then run the command again.

☐ Step 5 - Check the zip tool

What this does: the deployment scripts pack your code into a zip file, so they need zip. This prints its version.

COPY
zip --version | head -2

You should see: a copyright line and a version line such as This is Zip 3.0.

If it fails: macOS ships zip, so a failure usually means the command was mistyped. Copy it again exactly, including the vertical bar.

☐ Step 6 - Sign in to Azure

What this does: opens your browser so you can sign in, then stores a login token on your Mac. You do this once; it lasts for weeks.

COPY
az login

You should see: a browser window asking you to pick an account. After you sign in, Terminal prints a JSON list of your subscriptions, then asks Select a subscription and tenant (Type a number or Enter for no changes). Just press Return to keep the default - that is the subscription the guide was run with, and it is fine.

If it fails: if no browser opens, copy the URL that Terminal prints into your browser by hand. If it says the login expired later on, just run az login again.

☐ Step 7 - Check which subscription you are using

What this does: prints the name of the subscription that will be billed. If you have more than one, this tells you which one is active.

COPY
az account show --query name -o tsv

You should see: one line with your subscription's name, for example Data Engineering Suscription. That is the subscription this guide was run with; yours may be named differently.

If it fails: Please run 'az login' to setup account. means Step 6 did not complete. Run az login again.

☐ Step 8 - Register the service families

A brand new subscription has to be told about each family of services once. This is called registering a provider. It takes about a minute per family and only needs doing once per subscription.

What this does: registers the five service families this project uses. Run all five lines.

COPY
az provider register --namespace Microsoft.CognitiveServices
az provider register --namespace Microsoft.Search
az provider register --namespace Microsoft.Storage
az provider register --namespace Microsoft.Web
az provider register --namespace Microsoft.Insights

You should see: the first time, each command prints Registering is still on-going. You can monitor the status using 'az provider show -n <namespace>'. That message is normal, not an error.

If it fails: "already registered" is fine - nothing to do. Any other error usually means you are not signed in; run az login.

☐ Step 9 - Check that one of them finished

What this does: asks for the registration state of one family, so you know the wait is over.

COPY
az provider show --namespace Microsoft.Web --query registrationState -o tsv

You should see: Registered.

If it fails: if it prints Registering, nothing is wrong - wait a minute and run it again.

4. Create everything in Azure

4a. The easy way - one command

☐ Step 1 - Create all the resources at once

What this does: runs azure_setup/provision.sh, which creates the resource group, Azure OpenAI with two model deployments (gpt-5.1 and text-embedding-3-small), the AI Search service, the storage account and the PDF container. It takes about ten minutes.

COPY
SUFFIX=$SUFFIX bash azure_setup/provision.sh

You should see: a few Creating ... lines, then a block headed Done. Paste these lines into .env containing the endpoint, the two keys and the connection string. Keep that block - Section 5 uses it as a fallback.

If it fails: the most common error is The name ... is already taken. Pick a different SUFFIX, run the export lines again, and re-run this command. If it stops half-way, use 4b below to finish the missing pieces one at a time.

Two things worth knowing before you run it. (1) Re-running the script is safe: it does not duplicate anything, and resources that already exist are left as they are. (2) The search service is created in centralus, not in eastus2, because eastus2 was out of capacity for AI Search. Mixing regions is fine - the search service and the OpenAI resource do not have to sit together.

From this moment on, Azure is charging you. It is a small amount per hour, but it runs until you do Section 11. Do not stop half-way and forget.

4b. If you want to learn - the same thing one piece at a time

Use this if you want to see what each step does, or if the script stopped half-way. Each command is exactly what the script runs.

☐ Step 1 - Create the resource group

What this does: creates the folder that will hold everything. It is also the one thing teardown.sh deletes.

COPY
az group create --name "$RG" --location "$LOCATION" --output none

You should see: nothing. To confirm it exists, run az group exists --name "$RG", which prints true.

If it fails: Please run 'az login' means your session expired - run az login and retry.

☐ Step 2 - Create Azure OpenAI

What this does: creates the resource that hosts the language models. The --custom-domain gives it its own endpoint address.

COPY
az cognitiveservices account create --name "$OPENAI" --resource-group "$RG" \
  --location "$LOCATION" --kind OpenAI --sku S0 \
  --custom-domain "$OPENAI" --output none

You should see: nothing, after a minute or two.

If it fails: The name ... is already taken means someone in the world already used that name - change SUFFIX. Quota exceeded means your subscription has no room for this service in that region; try another region with export LOCATION=... and run the command again.

☐ Step 3 - Switch on the two models

On Azure you call a deployment name, not a model name. So each model is deployed under its own name. Run both commands.

What this does: deploys gpt-5.1 once, used for the answers, the router, the grader and the guardrail, and text-embedding-3-small for embeddings. One language model is enough, and it is the only one still deployable here: gpt-4o-mini is marked Deprecating and refuses to deploy, and gpt-4o is marked Legacy.

COPY
az cognitiveservices account deployment create --name "$OPENAI" --resource-group "$RG" \
  --deployment-name gpt-5.1 --model-name gpt-5.1 --model-version 2025-11-13 --model-format OpenAI \
  --sku-name GlobalStandard --sku-capacity 30 --output none
COPY
az cognitiveservices account deployment create --name "$OPENAI" --resource-group "$RG" \
  --deployment-name text-embedding-3-small --model-name text-embedding-3-small --model-version 1 \
  --model-format OpenAI --sku-name GlobalStandard --sku-capacity 120 --output none

You should see: nothing for each of the two. To check both, run the list command below; it prints gpt-5.1 and text-embedding-3-small.

COPY
az cognitiveservices account deployment list --name "$OPENAI" --resource-group "$RG" --query "[].name" -o tsv

If it fails: ServiceModelDeprecating means that model is being retired and cannot be deployed any more - use gpt-5.1 as above. Quota exceeded means your subscription has no room for that model in that region. To see what is actually on offer in your region, run this and pick a model whose lifecycle is GenerallyAvailable:

COPY
az cognitiveservices model list --location eastus2 --query "[?model.format=='OpenAI' && (contains(model.name,'gpt-5') || contains(model.name,'gpt-4.1') || contains(model.name,'gpt-4o'))].{name:model.name, version:model.version, lifecycle:model.lifecycleStatus}" -o table

You should see: a table of model names, versions and lifecycle states. If a model shows Deprecating or Legacy, choose a GenerallyAvailable one instead.

☐ Step 4 - Create Azure AI Search

What this does: creates the search service that will hold the index, in $SEARCH_LOCATION (centralus by default). --semantic-search free turns on the free semantic ranker, which allows 1,000 reranked queries a month at no extra cost.

COPY
az search service create --name "$SEARCH" --resource-group "$RG" --location "$SEARCH_LOCATION" \
  --sku basic --semantic-search free --output none

You should see: nothing, after a few minutes. Basic is billed per hour.

If it fails: InvalidResourceLocation or InsufficientResourcesAvailable means that region is out of capacity for AI Search - this is exactly what happened in eastus2. Keep SEARCH_LOCATION=centralus and run the command again. The name ... is already taken - change SUFFIX. If it says the service already exists in location centralus, the service is already there: leave it alone, or delete it before trying another region, because one name cannot exist in two regions.

☐ Step 5 - Create the storage account

What this does: creates the storage account that will hold your PDFs. --allow-blob-public-access false keeps every file private.

COPY

You should see: nothing.

If it fails: storage account names must be lowercase letters and digits only, with no dashes. If the name is taken, change SUFFIX.

5. Fill in the .env file

The .env file holds the settings and secret keys your code reads at start-up. It lives only on your Mac. It is already listed in .gitignore, so it will never be committed.

☐ Step 1 - Let the script fill it in

What this does: azure_setup/fill-env.sh asks Azure for the endpoint, the two keys and the storage connection string, and writes them into .env for you. It never prints a secret. If .env does not exist yet, it copies the template first.

COPY
export SUFFIX=12345
bash azure_setup/fill-env.sh

You should see: Checked .env (values are hidden): followed by 15 lines, each a setting name and the word filled, for example AZURE_OPENAI_API_KEY filled. If any line says EMPTY, stop there and ask for help - do not carry on.

If it fails: az: command not found means the PATH line is missing from this window - run export PATH="$PATH:$HOME/azure-cli-venv/bin". Please run 'az login' means your session expired - run az login. "resource not found" means SUFFIX is not the number you created the resources with.

☐ Step 2 - Check the result yourself

What this does: prints the name of each secret line and whether it has a value, without printing the value. This is the check that catches the empty lines.

COPY
awk -F= '$1 ~ /KEY|CONNECTION/ {print $1, (length($2)>0 ? "filled":"EMPTY")}' .env

You should see: three lines, all filled: AZURE_OPENAI_API_KEY, AZURE_SEARCH_API_KEY and AZURE_STORAGE_CONNECTION_STRING.

If it fails: an EMPTY line means the value is missing - run Step 1 again. Do not trust a check like sed 's/=.*/=<set>/' .env: it prints <set> even for a line that is empty after the equals sign, which is exactly how two values stayed empty the first time.

9b. See it in Application Insights (monitoring and the Application Map)

What this is. Application Insights is Azure's monitoring service. It records every request your function app receives and every call it makes out to Azure OpenAI, Azure AI Search and Blob Storage, and draws them as a picture called the Application Map. az functionapp create already made one for you, named func-supplychain-$SUFFIX, in the same resource group. The project's telemetry code (telemetry.py) switches itself on only when APPLICATIONINSIGHTS_CONNECTION_STRING has a value; with an empty value it does nothing at all.

Why the Application Map can be empty

An empty map on a first visit is common. These are the likely causes, in the order worth checking. On our run the map did fill in once traffic arrived, so cause 1 was the real one: the map itself is confirmed working, and an empty map almost always means nothing has called the app yet.

  1. Nothing has called the app yet. The map only draws boxes after requests arrive, so a brand-new app shows an empty canvas.
  2. Data takes 2-5 minutes to appear. Refresh the page, and widen the time range.
  3. The function app has no connection string, so the telemetry code stays switched off.
  4. The azure-monitor-opentelemetry package failed to start inside the app. The log stream shows why.
  5. The app itself is failing. An empty reply from curl means the app is not answering, and an app that does not answer sends nothing.

While the resources exist you pay for Azure AI Search (Basic, per hour), the App Service plan (B1, per hour), and per-token use of Azure OpenAI. The function app on the Consumption plan costs almost nothing when idle.

AI Search Basic bills every hour, whether you use it or not. The cheapest way to stop the meter is teardown: bash azure_setup/teardown.sh. Nothing else in this guide stops that hourly charge. The stray gpt-4o deployment left behind by the first failed attempt is harmless - it costs nothing while idle, and teardown removes it with everything else.

☐ Step 1 - Delete everything

What this does: asks you to confirm, then deletes the whole resource group and every resource inside it. This cannot be undone.

COPY
bash azure_setup/teardown.sh

You should see: Delete resource group 'rg-supply-chain-rag' and everything in it? Type yes to confirm:. Type yes and press Return. It then prints Deletion started. It finishes in a few minutes -- check the Azure portal.

If it fails: anything other than yes cancels safely and prints Cancelled. Nothing was deleted. The function app is inside the same resource group, so it goes too - there is nothing extra to remove.

☐ Step 2 - Confirm it is gone

What this does: asks Azure whether the resource group still exists.

COPY
az group exists --name "$RG"

You should see: false. If it still says true, the deletion is still running - wait a few minutes and check again.

If it fails: an empty $RG means the variable was lost in a new window. Run export RG=rg-supply-chain-rag and retry.

☐ Step 3 - Free the OpenAI names immediately (optional)

Azure OpenAI is soft-deleted for 48 hours, which blocks reusing the same names. teardown.sh ends with the two commands that purge it immediately. These are the same two commands, written out:

COPY
az cognitiveservices account list-deleted
az cognitiveservices account purge --name <name> --resource-group rg-supply-chain-rag --location <region>

You should see: the first command lists any soft-deleted OpenAI resources; the second prints nothing when it succeeds.

If it fails: replace <name> with your OpenAI resource name and <region> with your location. If the name is not in the list, there is nothing to purge.

To load .env, use this loop - never set -a; source .env. The storage connection string contains a ;, and source stops there, so the value arrives cut in half. The loop reads each line whole and splits at the first = only. It prints nothing.

COPY
while IFS= read -r line || [ -n "$line" ]; do case "$line" in ''|\#*) continue ;; esac; export "${line%%=*}=${line#*=}"; done < .env
